Пакеты: дополнительный контент из каталога#

В репозитории движка — код и минимум ассетов. Тяжёлый дополнительный контент (библиотеки PBR-материалов, их исходники, шаблоны проектов, наборы моделей, звук, эффекты) лежит в каталоге пакетов AIVERSE-PLUGINS. Проект скачивает только то, что использует.

ЧтоГде
Каталог: пакеты по разделам (materials/, textures/, templates/, models/, audio/, vfx/, ui/, scripts/, plugins/, tools/)AIVERSE-PLUGINS, <раздел>/<id>/aiverse.package.json
Архивы <id>-<версия>.zipGitHub-релизы <id>@<версия> репозитория AIVERSE-PLUGINS
Индекс (его читают движок и сайт)index.json в его main, пишет workflow publish
Клиентtools/pkg/aiverse_pkg.py (Python, только стандартная библиотека; --json у всех команд)
Кэш на компьютере~/.aiverse/packages/<id>/<версия>/ (AIVERSE_PACKAGES_HOME), скачанное проверяется по SHA-256
Сайтстраница Каталог (catalog.html): превью, описание, минимальная версия движка, скачивание

Как пользоваться#

python3 tools/pkg/aiverse_pkg.py search terrain              # ещё --category materials, --kind content
python3 tools/pkg/aiverse_pkg.py info terrain-pbr
python3 tools/pkg/aiverse_pkg.py add terrain-pbr --project ~/Games/MyGame
python3 tools/pkg/aiverse_pkg.py status --project ~/Games/MyGame
python3 tools/pkg/aiverse_pkg.py install --project ~/Games/MyGame   # после клонирования: всё из aiverse.lock
python3 tools/pkg/aiverse_pkg.py verify --project ~/Games/MyGame    # код 1, если установленные файлы изменены
python3 tools/pkg/aiverse_pkg.py remove terrain-pbr --project ~/Games/MyGame
python3 tools/pkg/aiverse_pkg.py fetch terrain-pbr-sources   # исходники для запекания: печатает папку в кэше
python3 tools/pkg/aiverse_pkg.py create <id-шаблона> ~/Games/New   # новый проект из пакета-шаблона
  • Пакеты content копируются в проект в папку install.mount (у terrain-pbr — materials/terrain); install.mergeJson добавляет их библиотеку материалов в materials.json проекта. Id, которые проект уже использует с другим значением, не перезаписываются (add останавливается; --force перезаписывает). Файлы становятся частью проекта, поэтому сборке не нужна сеть, а aiversebuild пакует только то, что лежит в проекте.
  • game.json → "packages": {"terrain-pbr": "^1.0.0"} — нужные диапазоны версий; aiverse.lock рядом фиксирует точную версию, хеш архива и хеш каждого установленного файла. Коммитьте оба файла.
  • Пакеты source (входные данные запекания) и другие данные инструментов в проект не копируются: инструменты вызывают aiverse_pkg.package_dir('<id>') и получают папку в кэше (скачивается один раз).
  • Пакеты template — целые папки проектов: create копирует такой пакет и ставит пакеты из его game.json.
  • Диапазоны версий: точная 1.2.3, ^1.2 (та же старшая), ~1.2.3 (та же средняя), >=1.0.0, *. У каждого пакета есть minEngine; add предупреждает, если этот checkout движка старше.
  • Без сети: AIVERSE_PACKAGES_OFFLINE=1 берёт только кэш и последний скачанный индекс.
  • C++-инструменты и редактор находят пакеты в кэше через engine/pack/Packages.h (aiverse::pack::cachedPackageDir("vegetation-pbr")). Игра кэш не читает.

Web-просмотрщик#

apps/catalogview (CMake -DAIVERSE_BUILD_CATALOGVIEW=ON, цель aiverse_catalogview) показывает материалы пакета или его glTF / GLB-модели через Renderer3D с орбитальной камерой. Пакет включает просмотр блоком viewer в манифесте; workflow pages каталога собирает view/<id>/<версия>/ (view.json и файлы ровно в том виде, в каком они опубликованы, текстуры в своём размере) и WebAssembly-просмотрщик из этого репозитория и выкладывает их на GitHub Pages каталога. В карточке каталога на сайте появляется кнопка 3D-просмотр: она открывает viewer/?src=../view/<id>/<версия>&lang=ru|en прямо в карточке.

  • Материалы: переключатель формы (сфера, куб, цилиндр, плоскость) над плиткой пола; плотность текселей одинакова на всех формах (один повтор на repeat метров, на замкнутых формах — целое число повторов, чтобы швы сходились). Панель показывает каждую карту текстуры с размером в пикселях и размером файла.
  • Модели: Авто LOD (подсвечен уровень, который выбрал рендер), фиксированный LOD 0…n или STRATA (кластеры строятся из модели при первом выборе; Кластеры раскрашивают их). Сетка показывает рёбра текущего уровня. Панель показывает треугольники по уровням, сгенерировал ли LOD движок, число кластеров STRATA и время их сборки, текстуры модели.
  • Все загрузки показывают анимированный знак AIVERSE (тот же, что на сайте, в Studio и веб-сборках; копии синхронизирует tools/branding/logo/loader.py, CTest branding_loader).

Параметры URL: src, item, shape=sphere|cube|cylinder|plane, lod=auto|strata|N, wire, clusters, lang. Проверка на компьютере: aiverse_catalogview --src <папка view> [--item N] [--shape S] [--lod auto|strata|N] [--wire] [--clusters] [--yaw град] [--pitch град] (AIVERSE_SCREENSHOT работает как в клиенте; каждое изменение печатает строку catalogview-info: {...} — тот же JSON, что получает страница).

Навыки указывают нужные пакеты#

Навык репозитория перечисляет нужные пакеты во frontmatter:

---
name: aiverse-terra-vegetation
description: ...
packages: vegetation-pbr, terrain-pbr
---

python3 tools/skills/catalog.py search|plan показывает их (contentPackages, в plan — готовые команды установки), а python3 tools/pkg/aiverse_pkg.py skill <id-навыка> --project P ставит их. Агенты: прежде чем выполнять такой навык в проекте, поставьте его пакеты; файлы пакетов в репозиторий движка не копируются.

Добавить или обновить пакет#

Pull request в AIVERSE-PLUGINS (его CONTRIBUTING.md); владелец проверяет и принимает. CI проверяет манифест, превью, лицензию и содержимое; после слияния publish выпускает версию и обновляет index.json, который движок и сайт читают напрямую. Маленькое содержимое лежит в files/ пакета, большое — archive по https или source (папка публичного GitHub-репозитория на зафиксированном коммите). Опубликованная версия не меняется: для изменений нужна новая version. Тяжёлые ассеты в репозиторий движка больше не коммитятся.
