## Root cause

A new standalone ECS gameplay skill was added in earlier Stage 1:
`skills/gameplay/aiverse-ecs-shared-static/SKILL.md`.

But AIVERSE's official skill catalog is generated by
`tools/skills/catalog.py`. Its `generate()` populates entries from
registered library packages, meta policies, and explicit standalone
skills/workflows. It did not register the ECS skill. Both CTests call
`validate()`, which compares **all physical skill paths** with
the registered paths, so both failed on the exact same missing ID.

Only inserting the entry in the generated JSON would leave the
`skill_catalog` CTest failing with `stale skill catalog; run generate`.

## Stage 8 changes

1. **`tools/skills/catalog.py`**:
   - Explicitly registers `aiverse-ecs-shared-static` as an
     opt-in `gameplay` skill with `runtime=none`,
     `side=tools`, `target=null`, `package=null`, no
     dependencies and existing source header
     `engine/sim/SharedStaticComponents.h`.
   - Adds searchable English/Russian vocabulary covering shared,
     static, ECS, prefab, memory, COW and rollback.
   - Does NOT invent a new standalone CMake library target: this
     capability is included in the engine as a header/API,
     and users link the existing project/native targets.

2. **`skills/catalog.json`**:
   - Adds the matching generated-format JSON record, kept in lexical
     `id` order between `aiverse-ecs-projectile-systems` and
     `aiverse-ecs-timed-mechanics`.
   - The previous 219-skill JSON was checked to be byte-identical to
     a two-space, UTF-8-preserving canonical JSON round trip before
     updating. The new JSON contains 220 skills.
   - Static cross-check verified the saved keywords match the
     registration string's token split and that the source entry
     is declared in `generate()`.

3. **`tests/skills/catalog_test.py`**:
   - Regression checks the new skill's exact stable ID, path,
     source, domain and runtime classification.
   - Checks direct search discoverability and that
     `m.plan(...,['aiverse-ecs-shared-static'],'both')` reads the
     skill file without generating fake native CMake linkage.

4. **`engine/scene/AGENTS.md`**:
   - Adds a repository skill-catalog rule: always register new
     skills with the generator, regenerate the JSON and run skill
     catalog/routing/audit checks. Prevents another orphan SKILL.
