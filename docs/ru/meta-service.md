# Полный мета-сервис (C++20)

Повторно используемый `aiverse::meta::Service` добавляет к существующим политикам экономики, таблиц лидеров и чата
друзей/кланы, предметы-экземпляры, права доступа (entitlements) и рейтинговые турнирные группы.
`engine/meta/Service.h` публичен и для движка, и для внешних нативных хостов на C++.
Не нужны ни Lua, ни GPU, ни сетевая библиотека, ни запущенный RTS-матч.

## Сборка и запуск

```sh
cmake -S tests/meta -B build/.temp/meta -DCMAKE_BUILD_TYPE=Debug
cmake --build build/.temp/meta -j 4
ctest --test-dir build/.temp/meta --output-on-failure

python3 tools/meta/scaffold.py --preset full --with-ui --out /path/to/game
python3 tools/meta/compose.py --project /path/to/game --validator build/.temp/meta/aiverse_meta_validate
python3 tools/meta/server.py --db /path/to/game/meta.sqlite user player1
# Copy the printed player token into the browser sign-in form.
python3 tools/meta/server.py --db /path/to/game/meta.sqlite serve \
  --binary build/.temp/meta/aiverse_meta_service \
  --config /path/to/game/meta/service.generated.json --ui /path/to/game/ui/meta
# Open http://127.0.0.1:8765
```

`economy.json`, `boards.json`, `chats.json` и `extensions.json` — редактируемые исходники.
`compose.py` проверяет их перед заменой `service.generated.json`; никогда не правьте этот
вывод вручную. Генератор отказывается перезаписывать определения или UI. `full` добавляет все новые
политики; minimal/mobile/competitive сохраняют свои более узкие предустановки. Удалите необязательные
разделы расширений, чтобы отключить функции. Перезапустите эталонный хост после изменения
конфигурации. Держите конфигурацию под версиями, пока есть незавершённые заказы/турниры.

Браузерный UI — работающий эталонный клиент с магазином, заданиями/ежедневными наградами/энергией,
таблицами лидеров, глобальным чатом, друзьями/кланами, коллекцией предметов, входящими и турнирами.
Текст вставляется через `textContent`; подписи RU/EN лежат в `ui/lang.json`; цвета/раскладка
заданы CSS-переменными. Без фреймворка и CDN. Он не монтируется автоматически в RmlUi.
Для нативного UI используйте ту же проекцию `view` и RPC-действия с локализацией хоста
и существующими компонентами RmlUi. Предложения за реальные деньги показывают передачу в магазин;
эталонный браузер не инициирует нативные платформенные платежи.

## Нативная интеграция

```cpp
#include "engine/meta/Service.h"
using namespace aiverse::meta;
auto definitions = ServiceConfig::parse(json);
Service service(definitions, savedSnapshot, atomicCompareAndSwap);
ServiceRequest request{"friends", "request", "stable-request-id", args};
auto reply = service.execute(authenticatedPrincipal, request, trustedUtcSeconds);
auto presentation = service.view(authenticatedPrincipal.player, trustedUtcSeconds);
```

Линкуйте `aiverse::meta`; зарегистрированные игровые модули используют `aiverse_native_use_meta(aiverse_native_ID)`.
Держите сервис в нативном хосте UI/сервисов, никогда в колбэках `tick` симуляции.
Используйте команды движка для любого проверенного мета-снимка, влияющего на матч.
`RemoteBackend` принимает функцию транспорта хоста и доставляет колбэки во время `pump`.
Хост владеет HTTPS, получением сессии, таймаутами/повторами и декодированием ответов. Все
вызовы завершения и pump происходят в потоке-владельце; адаптер не создаёт потоков.
Поздние колбэки после уничтожения адаптера безопасно попадают в ненаблюдаемую очередь.

## Состояние и полномочия

`Principal` приходит от хоста, а не из JSON клиента. Обычные игроки могут один раз создать свой
профиль, тратить свои балансы, забирать заработанные награды, отправлять сообщения и
выполнять разрешённые социальные действия. Только `authority=true` может выдавать награды/предметы,
записывать прогресс, отправлять очки, подводить итоги турниров, выполнять/отменять покупки,
модерировать сообщения или доставлять события провайдера прав доступа. Этот флаг — не проверка
чеков: хост должен сначала проверить событие платформы или авторитетный результат матча.

Серверный снимок владеет всеми профилями, дополнительным состоянием, социальными связями, кланами, таблицами,
чатами, турнирами и квитанциями. Команда изменяет копию, затем выполняет один
`Commit(expectedRevision, wholeSnapshot)` и при успехе публикует её. Неудавшиеся операции
и неудавшиеся коммиты оставляют прежнее состояние без изменений. Эталонный хост удерживает SQLite
`BEGIN IMMEDIATE` на время нативной обработки и замены снимка. Это сериализует
переводы между профилями и награды сезона, в том числе между процессами хоста.

ID операций ограничены областью аутентифицированного игрока, а сервис/действие/аргументы и
привилегия входят в их канонический отпечаток. Одинаковые повторы возвращают `Duplicate` с
исходным результатом. Изменённые данные возвращают `Conflict`. Порядок ключей JSON-объекта не
меняет отпечаток. Возраст аккаунта вычисляется из сохранённого времени создания профиля; обычные клиенты
не могут его передать. Другие метрики таргетинга берутся из авторитетных событий прогресса.
UTC читает хост; изменяющие вызовы отклоняют скачки часов
назад. Квитанции дедупликации нельзя удалять без явного протокола хранения для
повторов. Конструктор снимка принимает доверенное серверное хранилище, а не загруженные сохранения.

`view` показывает только текущий профиль (без квитанций операций), заявки в друзья
игрока, его клан, видимые каналы и публичные очки. Полный агрегированный
снимок HTTP-хост никогда не возвращает. ID незавершённых заказов и токены квитанций
есть только на сервере; эталонный view вырезает записи платёжных заказов.

## Каталог RPC

Все изменения требуют непустых `operation` (до 128 байт), `service`, `action` и
объекта `arguments`. ID — непустые строки не длиннее 128 байт. Суммы/время —
целые числа в 0..10^12. Ошибки используют `Code`: Ok=0, Duplicate=1, Invalid=2, Missing=3,
Unavailable=4, Insufficient=5, Limit=6, Conflict=7, Denied=8, Unsupported=9.

| Сервис | Действия | Аргументы / семантика |
|---|---|---|
| meta | view | без аргументов; проекция только для чтения |
| profile | create | без аргументов; настроенные начальные балансы, один раз |
| economy | buy, daily, energy, mail, reserve | `id`; reserve возвращает стабильный серверный ID заказа |
| economy | claim | `id`, `tier` с отсчётом от нуля |
| economy | event | полномочия: `metric`, неотрицательный `amount` |
| economy | grant | полномочия: набор `reward` |
| economy | deliver | полномочия: `id`, `reward`, `expires` (0 = без срока) |
| economy | fulfill, cancel | полномочия: `order`, `token` для fulfill; глобально уникальный проверенный платёжный токен |
| friends | request, accept, reject, remove, block, unblock | `target`; симметричная дружба, направленная блокировка |
| clan | create, join, leave | `id`; join требует действующего приглашения |
| clan | invite, kick, transfer | `id`, `target`; авторизация владельца/офицера |
| clan | role | только владелец: `id`, `target`, `role` = member/officer |
| clan | donate | `id`, `asset`, положительный `amount`; атомарное списание + накопительный банк |
| clan | goal | `id`, `goal`; участник забирает один раз при достижении порога банка |
| items | grant | полномочия: `id` экземпляра, `type` определения |
| items | redeem | новый `id` экземпляра, `type` определения; атомарно расходует один настроенный ресурс |
| items | upgrade, salvage, unequip | `id` экземпляра |
| items | equip | `id` экземпляра, совместимый `slot`; занятые слоты отклоняются |
| items | merge | `id` остающегося экземпляра, `inputs` = другие различные ID экземпляров |
| entitlement | grant, revoke | полномочия: `id`, уникальное `event` провайдера, возрастающий `sequence`, `start`, `end` |
| board | submit | полномочия: `id`, `score` |
| tournament | join | `id`; сервер распределяет в когорту по лиге и порядку прибытия |
| tournament | submit | полномочия: `id`, `score`, записанный игрок |
| tournament | settle | полномочия: `id`, в момент окончания или позже, все группы в одной транзакции |
| chat | send | `id`, `text`, необязательный `kind` |
| chat | read, report, delete | `id`, `sequence`; delete требует полномочий |
| chat | block, unblock | `id`, `target` |
| chat | mute | полномочия: `id`, `target`, `until` |

## Конфигурация расширений

Полное проверенное определение см. в `examples/meta/service.json`.

- **initial:** стартовый набор балансов. Применяется только при создании профиля.
- **friends:** maxFriends/maxRequests (по умолчанию по 100, ограничено 1..10000).
- **clans:** maxMembers (50), inviteSeconds (86400), createCost, именованные цели.
  Цель = asset/amount/reward. Пожертвования — накопительные вклады, а не кошелёк, из которого
  можно выводить средства. Прежде чем владелец непустого клана уйдёт, требуется передача владения.
  Офицеры приглашают/исключают обычных участников; только владелец повышает/исключает офицеров.
  Каждый игрок может состоять в одном клане. Новые участники могут забирать уже выполненные общие цели.
- **items:** именованные определения с необязательными asset, slots, upgradeCosts (за следующий уровень), набором salvage,
  необязательными mergeCount/mergeTo, метаданными. Экземпляры имеют стабильные ID/тип/уровень; merge
  требует одинаковых типов и уровней, расходует ровно mergeCount экземпляров, сохраняет
  выбранный ID и сбрасывает его уровень до нуля на целевом типе. Экипированные предметы
  нельзя израсходовать. Улучшение/разбор и изменения балансов коммитятся вместе.
  Необязательный asset сопоставляет награды-балансы из магазина/заданий/почты созданию экземпляров через
  items.redeem; браузерная коллекция предлагает такое преобразование, когда ресурс есть.
  Это постоянный инвентарь экземпляров, а не стековый инвентарь симуляции.
- **entitlements:** именованные определения тегов/метаданных. Проверенные события провайдера заменяют
  авторитетный интервал права доступа. End=0 означает бессрочно; end не включается.
  Sequence должен возрастать, а ID событий нельзя повторно использовать для разных игроков. Продления
  используют новое событие провайдера и обновлённый интервал; возвраты отзывают право. Для восстановления воспроизведите
  исходную операцию или отправьте более новое авторитетное событие снимка. Несколько
  покупок у провайдера для одного права доступа должен согласовывать адаптер провайдера.
- **tournaments:** каждый ID — неизменяемый сезон: start/end, groupSize (2..10000),
  число повышений/понижений, maxLeague, награды по местам и обычная политика таблицы.
  Группы заполняются в порядке записи внутри лиги; ничьи разрешаются правилами таблицы и ID игрока.
  Повышение/понижение использует упорядоченную позицию (уникальную), награды — отображаемое место.
  Маленькие группы сначала распределяют повышения. Новый сезон = новый ID. Запись фиксирует
  членство в группе, не выдумывая очки. Места/награды или изменения лиги получают только
  игроки с проверенными отправленными очками; не отправившие сохраняют свою лигу. Подведение итогов
  один раз записывает результаты, лигу и почту с наградами;
  входящие не дают потерять выплаты из-за лимита инвентаря при подведении итогов. Результаты
  подведённого сезона не меняются при повторных попытках получения.

## Эталонный HTTP-хост и эксплуатационные ограничения

`server.py` — настоящий локальный HTTP-эндпоинт на основе SQLite и исполняемого файла на C++.
Он хранит SHA-256-хеши случайных bearer-токенов, проверяет срок действия, отклоняет неизвестные
поля запроса, ограничивает размер тела и вырезает полное состояние из ответов. `user PLAYER`
выдаёт токен уже идентифицированному игроку; `revoke PLAYER` отзывает сессии.
`user PLAYER --authority` создаёт доверенные серверные учётные данные; не помещайте их в
UI игрока. Провайдер аутентификации игры должен обменивать проверенную идентичность на сессии.
Привязка аккаунтов OAuth и база паролей не входят в комплект.

Он намеренно привязывается к 127.0.0.1. Развёртывание в интернете требует TLS/обратного прокси,
ограничений частоты/соединений, выдачи идентичностей, наблюдаемости и резервных копий. Установите
`--public-origin https://game.example` в точный origin браузера, когда работаете за TLS-
прокси; заголовкам перенаправленной схемы доверия нет. Ничего из этого
этим изменением не развёрнуто. Хост запускает один нативный подпроцесс на запрос и
хранит один агрегированный снимок: подходит для интеграции/эталона и небольших проектов,
но не является архитектурой базы данных для MMO. Представления для чтения содержат первые 50 строк
таблицы лидеров/чата; лежащие в основе API Leaderboard/Chat предоставляют нативным хостам страницы и курсоры.
Настроенные эталонные каналы чата глобальны. Приватные/клановые области должны использовать
колбэк авторизации Chat в хосте проекта; не называйте глобальные каналы
приватными по их именам. Группировка турниров — это рейтинговые когорты, а не сетки
или матчмейкинг с учётом задержки. Миграция состояния и архивирование истёкших сезонов остаются
явными обязанностями хоста. Не удаляйте и не изменяйте определения незавершённых сезонов.

## Проверка

`tests/meta` охватывает ошибки политик, авторизацию, повторы/конфликтующие данные, владение
квитанциями между игроками, инварианты кланов, расходование экземпляров, истечение/отзыв прав доступа,
подведение итогов турниров, сохранение/восстановление и сбой CAS. `backend_test.py` выполняет
настоящий HTTP-парсер/обработчик через сокеты в памяти, вызывает нативный бинарник и проверяет
перезапуски SQLite; он не проверяет слушающий сетевой сокет или TLS. Запускайте сервис
локально и проверяйте экраны браузера перед выпуском изменений UI. Чисто нативные библиотеки
остаются независимо собираемыми через `examples/meta`.

### Проверка в этом изменении

- macOS / AppleClang 17: девять отдельных проверок CTest прошли под ASan + UBSan.
- Внешний нативный потребитель и реальный тест линковки нативного модуля прошли; корневые цели CMake
  aiverse_meta_service/aiverse_meta_service_tests/aiverse_meta_validate собрались.
- Проверки библиотек foundation/gameplay/application и перенесённый нативный потребитель прошли.
- Аутентификация HTTP, проверки origin, сохранность при перезапуске SQLite и нативная обработка
  проверены через сокеты в памяти. Слушающие сокеты были запрещены окружением.
- QA скриншотов браузера заблокировала политика браузера для file URL. Синтаксис JavaScript UI
  и JSON проверены, но визуальная интеграция и интеграция с нативным RmlUi остаются непроверенными.
- Сборки GCC, Windows, Android, iOS и web не запускались. Пути GPU/шейдеров не менялись.
- Облачного развёртывания и опубликованной сборки движка не было. Интеграция требует
  обычных проверок выпуска ветки main перед публикацией обеих платформ редактора.
