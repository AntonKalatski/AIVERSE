# LUMA: динамический непрямой свет

LUMA добавляет к обычному прямому освещению один отскок рассеянного света через сетку проб.
Режим явный: сам по себе он не включается, не забирает себе прямое освещение и ничего не
пишет в состояние симуляции или ECS.

## Подключение из нативного кода

Для трассировки на CPU с бюджетом времени — `engine/render/GiMainCpuBridge.h`, для
ограниченных вычислений на Metal/Vulkan — `engine/render/GiMainGpuBridge.h`. Оба принимают
неизменяемый `GiChunkedGeometrySnapshot`, стабильные ревизии геометрии, источники
`GiMovingLight` в линейном RGB и необязательный `GiEnvironmentLight`, который влияет только
на непрямой свет. Рабочий пример нативного хоста — `apps/renderbench/DynamicGiHost.h`.

1. Пока массивы мешей на CPU ещё не освобождены, соберите неизменяемые блоки
   непрозрачных отбрасывателей с диффузным альбедо материала. Бенчмарк сохраняет
   CPU-геометрию у анимированных ассетов, для которых это включено, и сам публикует
   блоки в текущей позе.
2. Создайте фиксированную решётку проб. GPU поддерживает до 8192 треугольников,
   16 источников, 32 проб за вызов и 8–64 луча на пробу. CPU поддерживает 8–128 лучей
   и сам подстраивает число проб за кадр. Решётка ограничена 20000 проб. Бюджет CPU —
   цель планировщика, а не гарантия времени кадра для отдельного луча.
3. В потоке рендера опубликуйте снимки геометрии, света и окружения и обновите их до
   графических проходов. Публикация на GPU требует активного кадра устройства. Отложенные
   публикации повторяйте после того, как завершатся прежние барьеры вычислений **и
   графических читателей**. Отклонённые исходные данные нельзя выдавать за текущие.
4. Вызовите `renderer.beginScene(...)`, затем `renderer.setDynamicGiOverlay(bridge)`
   для каждого вида. `beginScene` снимает прежнее подключение. Мост должен жить
   дольше всех отправленных отрисовок. Материалы Shader Graph с текстурами отдают
   tex13 под GI и сдвигают свои сэмплеры на tex14+. Пока GI подключён, GPU-инстансинг
   и ICB рисуются обычными вызовами. PBR-материалы поддерживают High/Low и умножают
   GI на AO материала.
5. Рельеф и собственные конвейеры привязывают GI после выбора шейдера: полный
   встроенный рельеф — U6/tex21; компактный рельеф уровня 0 — только tex8, без
   запечённого света, детали и трассировки. Обычные модели и свои сэмплеры — tex13.
6. Отключите приёмники, дождитесь настоящего простоя GPU, затем вызовите
   `shutdownAfterGpuIdle()` до уничтожения устройства. Возраст кадра на CPU не заменяет
   завершения работы GPU.

Завершение работы планировщика на GPU подтверждается барьерами.
`computeDispatchSucceeded()` значит, что команды записаны, а не что GPU их выполнил.
При частично прошедшей загрузке результат остаётся скрытым, а геометрия
восстанавливается целиком. Отказы по разным источникам независимы: обновление
окружения не возвращает отклонённые источники света.

## Рецепт для renderbench

Добавьте в сцену нативного renderbench необязательный объект `dynamicGI`:

```json
"dynamicGI": {
  "backend": "auto",
  "origin": [-12, 0, -6],
  "dimensions": [8, 4, 4],
  "spacing": 3,
  "samples": 32,
  "distance": 20,
  "cascades": 1,
  "cpuBudgetMs": 2,
  "sunDirection": [0.35, 1, 0.55],
  "sunColor": [1, 0.96, 0.9],
  "sunIntensity": 3,
  "skyIntensity": 0
}
```

`auto` использует вычисления на GPU, только если это позволяют устройство и сцена;
иначе вся геометрия остаётся на CPU. `gpu` явно завершится ошибкой, если GPU-путь
недоступен; `cpu` принудительно включает переносимый путь. Источники не обрезаются
молча. Точечные источники рецепта переводятся из хранимого рендером sRGB обратно в
линейный цвет. Цвета окружения выше уже линейные и влияют только на непрямой свет;
настройки прямого солнца и неба неявно не копируются.

Геометрия делится на пространственные блоки размером примерно с `distance`. На GPU
резидентны только блоки, до которых может дотянуться луч GI (`GiGpuResidencyPlanner`),
поэтому мир больше бюджета в 8192 треугольника остаётся на GPU, пока достижимая часть
в него помещается. `cascades` (1..3, только GPU) добавляет вложенные решётки вокруг того
же центра: каскад k имеет шаг `spacing`·2^k и дальность `distance`·2^k. Все каскады
делят один атлас GI (texture 13, U6 — девять float4). Точка берёт самый мелкий каскад,
в который попадает, и плавно переходит в следующий у его края.

Бенчмарк ждёт начальной сходимости перед замеряемыми кадрами и сообщает
`dynamicGiBackend`, `dynamicGiFallback`, `dynamicGiTriangles` и
`dynamicGiConvergenceMs`. GI подключается заново для каждого вида камеры.

Бенчмарк не допускает одновременно `probeGI`/`staticPointBounce`: эти рецепты
используют те же источники. Его экранный диффузный отскок выключен, пока активен
dynamicGI. Прямое освещение и постобработка остаются независимыми. Анимированные ассеты
используют одну позу на рендер, непрямой GI и тени LUMA. Проверочный хост держит эту
позу, пока GI не сойдётся, и не претендует на задержку переноса света для анимации в
реальном времени. Тайминги отправленных кадров не включают обновления только ради
сходимости (см. `lightingCadence`). Интеграция в редактор — отдельный этап.

## Проверка и ограничения

Все сборки и временные каталоги компилятора для этой работы лежат на KINGSTON:
`/Volumes/KINGSTON/AIVERSE/Builds/.temp/lighting-completion-20261120`.
Зарегистрированные проверки запускаются командой
`./run-tests.sh --no-build --build-dir <root>/build --filter '^lighting_'` после сборки
нужных целей. Включите `AIVERSE_BUILD_HDR_TESTS`, `AIVERSE_BUILD_RENDERBENCH`,
`AIVERSE_BUILD_TESTS`; `AIVERSE_VULKAN` дополнительно собирает тесты компиляции SPIR-V.

Пиксельные тесты на Metal и настольном GL покрывают модели и рельеф как приёмники,
сброс для каждого вида, удаление и возврат источников и совпадение CPU и GPU.
Приёмка нативного хоста загружает настоящий glTF, проверяет итоговый JSON и сравнивает
снятый RGB, так что нулевой код выхода окна не скроет ошибку сцены. Бэкенд Vulkan и
SPIR-V для GI компилируются локально; выполнение на GPU через Vulkan на этом Mac не
проверено (нет загрузчика). Проверка компактного шейдера на настольном GL — не
утверждение о производительности на устройствах с GLES.

Это ограниченная интерполяция L1 первого отскока, а не многоотскоковый path tracing,
не GI отражений, не потоковая загрузка бесконечного мира, не перенос проб и не защита
от всех утечек света сквозь тонкие стены. Производительность и приёмка на мобильных
устройствах и Vulkan — отдельные этапы; качество по умолчанию не менялось.

## Снимки геометрии в позе

`giModelGeometry(model, objectTransform, &pose)` из `GiModelGeometry.h` снимает
непрозрачные отбрасыватели с жёсткой анимацией узлов, позициями морфов и
нормализованными байтовыми весами скиннинга. Он использует `worldMatrices` /
`paletteMatrices`; преобразования суставов скиннинга заданы в пространстве модели,
поэтому трансформ узла меша не применяется дважды. Морфы идут до скиннинга. Для моделей,
чьи снимки пересобираются после загрузки, сохраняйте на CPU вершины, индексы, дельты
морфов и образцы изображений через `uploadModel(..., true)`. Без данных позы или морфов
снимок отклоняется, а не застывает молча в позе привязки.

Публикуйте результат как замену блока в `GiChunkedGeometryBuilder`; старые снимки
сохраняют прежнюю геометрию для трассировки, которая уже идёт. Адаптер даёт снимок, но
не планирование и не автоматическое отслеживание хоста. Альфа-маски, прозрачные
поверхности и смещение вершин в Shader Graph этим приближением непрозрачными
треугольниками не передаются. Альбедо текстуры берётся ограниченным усреднением.

Нативный хост `AnimatedLightingGeometry` переиспользует неизменённые статичные блоки и
пересобирает только блоки анимированных отбрасывателей. Он публикует монотонные ревизии
и для GI на CPU/GPU, и для LUMA. Отчёты показывают animatedLightingCasters,
lightingGeometryRevision и lightingSnapshotTriangles. Ошибка вместимости геометрии
отклоняет вид; актёры никогда молча не выбрасываются, чтобы влезть в бюджет GPU.
`bake:false` сохраняет явное исключение ассета из отбрасывателей. Этот хост с
фиксированной нагрузкой держит выбранную позу, пока идут вычисления и сходимость, и
затем рисует ту же позу; игровой хост выбирает и измеряет частоту обновления сам.

## Настройка в Studio

Необязательный блок карты `renderLighting` версии 1 проверяет RenderLightingSettings.
Панель Lighting в Studio поддерживает сохранение, отмену и повтор. RenderLightingRuntime
использует общие владельцы DynamicGiHost и LumaHost; вьюпорт рисует существующие прокси
рельефа и документа как PBR-геометрию. Это не полное совпадение с предпросмотром
игровых ассетов. Панель показывает фактический бэкенд, сходимость и откат.

## Экспериментальный Metal ICB

Texture13 динамического GI входит в буфер аргументов фрагментного шейдера Metal ICB;
U6 сохраняется вместе с другими юниформами каждой отправки. Оба источника GI, CPU и
GPU, проходят аналитические пиксельные тесты с настоящими отправками команд,
записанными на GPU. Это не включает экспериментальный ICB по умолчанию и не говорит о
производительности ICB во всём движке.

## Воспроизводимые замеры Release

`tools/renderbench/lighting_release_acceptance.py --binary <arm64-renderbench>
--scene <GI-scene.json> --output <каталог-артефактов-на-KINGSTON>` записывает
последовательность ВЫКЛ/ВКЛ/ВЫКЛ: 30 кадров прогрева и 120 замеряемых, камера и поза
фиксированы. Запись кадра на CPU, кадр CPU и выполнение на GPU выводятся отдельно от
загрузки и сходимости GI. Отчёты не-Release, не-arm64 и неполные отклоняются; темп окна
нельзя выдавать за FPS. Для прямого освещения используйте `--feature luma`.

## Совместная работа ресурсов в main (2026-11-20)

Модели без виртуальных материалов сохраняют GI на texture13/U6. Если материал
использует виртуальную выборку, его атлас, таблица страниц и U6 остаются как есть;
GI занимает U7 и первую текстуру после таблицы (после альфа-покрытия, если оно есть).
Источники Shader Graph остаются на 13+ для виртуальных материалов и сдвигаются на 14+
для невиртуальных материалов с GI. Переполнение ресурсов отклоняет конвейер с явной
диагностикой. Виртуальный материал + GI и граф + GI отправляются обычным путём через
CPU; экспериментальный ICB сохраняет ранее проверенный ABI GI для простого PBR. Эти
откаты дают то же затенение на GPU, а не второй решатель освещения.

GI на Vulkan использует общий ABI вычислений TextureResources: буферы 12..15, образ
хранилища 0 и блок юниформ std140 16 через bindComputeStorageTexture и dispatchChecked.
Отдельного конкурирующего бэкенда вычислений на Vulkan больше нет. GLSL рельефа выдаёт
буквальные имена сэмплеров для транслятора привязок Vulkan. Подготовленные кадры
рельефа LENS ставят варианты конвейера GI до публикации; обратные вызовы хранят
неизменяемые привязки текстур, а не изменяемых владельцев.
